## 1. 实验目标

本实验旨在设计并实现一个支持 MIPS 指令集的五级流水线 CPU。设计需满足以下核心要求：

1. **指令集支持**：涵盖算术逻辑运算（ADD/SUB/AND/OR/SLT等）、立即数运算（ADDI/LUI等）、乘除法（MULT/DIV/MFLO等）、分支跳转（BEQ/J/JAL/JR等）以及访存指令（LB/LH/LW/SB/SH/SW）。
2. **流水线架构**：实现标准的 IF、ID、EX、MEM、WB 五级流水线。
3. **冲突处理**：通过数据旁路（Forwarding）解决数据冒险，通过流水线停顿（Stall）解决 Load-Use 冒险，通过冲刷（Flush）解决控制冒险。
4. **特殊功能**：集成乘除法器（MDU），支持非对齐内存访问，并实现 Syscall（1号输出整数，10号停机）。

## 2. 总体设计方案

### 2.1 数据通路设计

CPU 采用经典的五级流水线结构：

* **IF (取指)**：包含 PC 和指令存储器。PC 值根据分支逻辑或顺序执行更新。
* **ID (译码)**：包含寄存器堆（Register File）和控制器。在此阶段完成指令译码、寄存器读取、立即数扩展以及分支判定（为了减少分支开销，将分支判定提前至 ID 阶段）。
* **EX (执行)**：包含 ALU 和 MDU。处理算术运算、地址计算。ALU 输入源通过多路选择器选择寄存器值、立即数或旁路数据。
* **MEM (访存)**：处理数据存储器的读写。针对 LB/LH/SB/SH 等指令，在模块内部通过位操作实现非对齐访问。
* **WB (写回)**：将运算结果或内存数据写回寄存器堆。

### 2.2 冲突处理机制

* **数据冒险**：设计了 `ForwardingUnit`，支持 EX 级和 MEM 级的数据前递。当检测到 EX 或 MEM 阶段的目标寄存器与当前 ID/EX 阶段的源寄存器冲突时，直接将结果旁路到 ALU 输入，避免停顿。
* **Load-Use 冒险**：设计了 `HazardDetectionUnit`。当检测到上一条指令是 Load 且目标寄存器被当前指令使用时，强制流水线停顿一个周期（Stall PC 和 IF/ID，Flush ID/EX）。
* **控制冒险**：对于分支和跳转指令，一旦在 ID 阶段判定跳转发生，立即冲刷 IF/ID 流水线寄存器，将下一条错误预取的指令清除。

## 3. 关键模块实现细节

### 3.1 控制器 (Controller)

控制器采用组合逻辑实现，根据 `opcode` 和 `funct` 域生成流水线各阶段所需的控制信号（如 `reg_write`, `alu_src`, `mem_read` 等）。对于乘除法指令，生成 `mdu_start` 和 `mdu_op` 信号与 MDU 模块交互。

### 3.2 乘除法器集成 (MDU Integration)

使用了提供的 `MultiplicationDivisionUnit` 模块。在 `TopLevel` 中增加了 `stall_mdu` 逻辑：

```verilog
wire stall_mdu = (id_ex_mdu_start || id_ex_mdu_read) && mdu_busy;
```

当 MDU 处于 `busy` 状态时，流水线在 EX 阶段阻塞，直到运算完成。

### 3.3 寄存器堆的内部转发 (Register File Internal Forwarding)

在调试过程中发现，当 `jal` 指令（在 WB 阶段写 `$ra`）紧接着 `jr $ra` 指令（在 ID 阶段读 `$ra`）执行时，由于读写在同一周期，`jr` 会读到旧值 0。
为解决此 RAW（写后读）冲突，修改了 `RegisterFile.v`，增加了内部转发逻辑：若读地址等于写地址且写使能有效，直接输出写入数据。

```verilog
assign read_data1 = (read_addr1 == 5'd0) ? 32'b0 : 
                    ((read_addr1 == write_addr) && reg_write) ? write_data :
                    registers[read_addr1];
```

### 3.4 非对齐访存

在 `DataMemory` 模块中，利用 `case` 语句处理 `size` 和地址低两位 `offset`。

* **读操作**：先读出 32 位字，再根据 `offset` 截取 8 位或 16 位，并根据指令类型（如 `LB` vs `LBU`）进行符号扩展或零扩展。
* **写操作**：先读出目标地址的旧字，修改对应的字节或半字，再将合并后的新字写回内存。

## 4. 仿真与调试

### 4.1 测试环境

* **仿真工具**：Vivado Simulator (xsim)
* **汇编工具**：Mars (CompactDataAtZero 配置)
* **测试用例**：`test_50.asm` (涵盖所有要求指令的综合测试)

### 4.2 调试过程记录

在开发过程中主要遇到了以下问题并予以解决：

1. **地址空间映射问题**：

   * **现象**：Mars 默认 Text 段从 0x3000 开始，而硬件默认从 0x0 开始，导致指令无法正确加载。
   * **解决**：调整 `ProgramCounter` 复位值和 `InstructionMemory` 基地址为 `0x3000`，并在汇编文件中指定 `.text 0x3000`。
2. **分支延迟槽问题**：

   * **现象**：分支跳转后，预期不执行的指令被执行了，或者跳转目标计算错误。
   * **解决**：在汇编测试代码的所有分支/跳转指令后手动添加 `nop` 指令作为延迟槽，并在硬件中确保 `flush_if_id` 逻辑正确清除错误路径的指令。
3. **JR 跳转失败**：

   * **现象**：测试点 7 中，`jr $ra` 跳转目标地址为 0，导致程序跑飞。
   * **分析**：波形显示 `$ra` 在 ID 阶段读取时仍为 0，而此时前一条 `jal` 指令正在 WB 阶段写入正确地址。
   * **解决**：如前文所述，在寄存器堆中实现了写优先（Write-Through）逻辑。

### 4.3 仿真结果

运行 `test_50.asm` 仿真，所有测试点（立即数、ALU、移位、MDU、访存、分支跳转）均通过。
