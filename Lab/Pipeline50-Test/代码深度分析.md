### 问题1️⃣：怎么识别后执行的指令是否用了前执行的指令还没写回寄存器的内容？

#### 答案定位：[ForwardingUnit.v](src/ForwardingUnit.v#L1-L30)

```verilog
// ForwardingUnit.v 第13-26行
always @(*) begin
    forwardAE = 2'b00;  // 默认：使用寄存器文件数据
    forwardBE = 2'b00;

    // 检测 EX/MEM 阶段的数据冒险（前一条指令）
    if (ex_mem_reg_write && !ex_mem_mem_to_reg && 
        (ex_mem_dest != 5'd0) && (ex_mem_dest == id_ex_rs)) begin
        forwardAE = 2'b10;  // 从 EX/MEM 转发
    end 
    // 检测 MEM/WB 阶段的数据冒险（前两条指令）
    else if (mem_wb_reg_write && 
             (mem_wb_dest != 5'd0) && (mem_wb_dest == id_ex_rs)) begin
        forwardAE = 2'b01;  // 从 MEM/WB 转发
    end
    // 对 rt 寄存器做同样检测...
end
```

**识别机制核心逻辑**：
| 比较项                    | 含义                                                    |
| ------------------------- | ------------------------------------------------------- |
| `ex_mem_dest == id_ex_rs` | EX阶段指令的源寄存器rs 是否等于 MEM阶段指令的目标寄存器 |
| `mem_wb_dest == id_ex_rs` | EX阶段指令的源寄存器rs 是否等于 WB阶段指令的目标寄存器  |
| `ex_mem_reg_write`        | 前一条指令是否要写寄存器                                |
| `ex_mem_dest != 5'd0`     | 目标不是$0寄存器（$0恒为0，不需要转发）                 |

### 问题2️⃣：指令stall在代码里什么地方涉及？如何判断需要stall几个周期？

#### 答案定位：[HazardDetectionUnit.v](src/HazardDetectionUnit.v) + [TopLevel.v](src/TopLevel.v#L195-L202)

**（A）Load-Use冒险检测** —— [HazardDetectionUnit.v](src/HazardDetectionUnit.v#L12-L19)

```verilog
// 检测 load-use 冒险（lw 后紧跟使用该数据的指令）
wire hazard_rs = id_use_rs && (id_ex_dest != 5'd0) && (id_ex_dest == if_id_rs);
wire hazard_rt = id_use_rt && (id_ex_dest != 5'd0) && (id_ex_dest == if_id_rt);
wire load_use_hazard = id_ex_mem_to_reg && (hazard_rs || hazard_rt);

assign stallF = load_use_hazard;  // 暂停 IF 阶段
assign stallD = load_use_hazard;  // 暂停 ID 阶段
assign flushE = load_use_hazard;  // 清空 EX 阶段（插入气泡）
```

**Load-Use冒险只需要stall 1个周期**，因为：
- 第1周期：lw在EX阶段，后续指令在ID阶段 → 检测到冒险，stall
- 第2周期：lw在MEM阶段，后续指令仍在ID阶段 → lw读取内存
- 第3周期：lw在WB阶段，后续指令进入EX阶段 → 可以通过MEM/WB转发获取数据

**（B）MDU（乘除法）stall** —— [TopLevel.v](src/TopLevel.v#L195-L202)

```verilog
// MDU stall 逻辑
wire stall_mdu = (id_ex_mdu_start || id_ex_mdu_read) && mdu_busy;

assign stallF = hazard_stallF || stall_mdu;  // 两种stall来源
assign stallD = hazard_stallD || stall_mdu;
assign stallE = stall_mdu;
assign flushE = hazard_flushE && !stall_mdu;
assign flushM = stall_mdu;
```

**MDU stall周期数由 `mdu_busy` 信号决定**：
- 乘法：5个周期 (`MUL_DELAY_CYCLES = 5`)
- 除法：10个周期 (`DIV_DELAY_CYCLES = 10`)

### 问题3️⃣：旁路机制是怎么跨流水线转发的？如何判断使用旁路数据还是真的寄存器数据？

#### 答案定位：[TopLevel.v](src/TopLevel.v#L295-L310)

**转发路径选择MUX**：

```verilog
// TopLevel.v 第305-308行
// forwardA_value 选择：EX阶段指令的第一个操作数来源
assign forwardA_value = (forwardAE == 2'b10) ? ex_mem_alu_result :   // 从 MEM 阶段转发
                        (forwardAE == 2'b01) ? reg_write_dataW :     // 从 WB 阶段转发
                                               id_ex_reg_data1;      // 使用寄存器文件原值

assign forwardB_value = (forwardBE == 2'b10) ? ex_mem_alu_result :
                        (forwardBE == 2'b01) ? reg_write_dataW :
                                               id_ex_reg_data2;
```

**转发数据流图**：

```
                    ┌─────────────────────────────────────────┐
                    │           ex_mem_alu_result             │
                    │              (MEM阶段结果)               │
                    └───────────────────┬─────────────────────┘
                                        │ forwardAE=2'b10
                                        ▼
┌─────────┐     ┌─────────┐     ┌──────────────┐     ┌─────────┐
│ ID/EX   │────▶│   MUX   │────▶│     ALU      │────▶│ EX/MEM  │
│reg_data1│     │         │     │              │     │         │
└─────────┘     └────┬────┘     └──────────────┘     └─────────┘
                     │ forwardAE=2'b00                    
                     │ (使用原值)                         
                                        ▲
                                        │ forwardAE=2'b01
                    ┌───────────────────┴─────────────────────┐
                    │           reg_write_dataW               │
                    │              (WB阶段结果)                │
                    └─────────────────────────────────────────┘
```

**判断逻辑汇总表**：

| forwardAE值 | 条件                               | 数据来源                        |
| ----------- | ---------------------------------- | ------------------------------- |
| `2'b00`     | 无冒险                             | `id_ex_reg_data1`（寄存器文件） |
| `2'b10`     | EX/MEM阶段指令写同一寄存器且非load | `ex_mem_alu_result`             |
| `2'b01`     | MEM/WB阶段指令写同一寄存器         | `reg_write_dataW`               |

**为什么优先检测EX/MEM？** —— 因为它是更近的指令，数据更新。

## 三、作业 II.B：乘法单元机制分析

### 参考代码再贴一遍

```mips
1  mult $1, $2          # 启动乘法，MDU开始计算
2  addu $10, $11, $12   # 无关指令
3  mflo $3              # 读取乘法结果低32位
4  mfhi $4              # 读取乘法结果高32位
5
6  addu $3, $3, $4      # 使用乘法输出
7
8  mult $1, $2          # 另一个乘法
9  mflo $3
10 mfhi $4
11 mult $5, $6          # 第三个乘法
12 mflo $7
13 mfhi $8
14 addu $3, $3, $7      # 处理结果
```

### MDU核心机制 —— [MultiplicationDivisionUnit.sv](src/MultiplicationDivisionUnit.sv)

```systemverilog
// 关键参数
`define MUL_DELAY_CYCLES 5   // 乘法需要5个周期
`define DIV_DELAY_CYCLES 10  // 除法需要10个周期

// busy信号：remainingCycleCount不为0时MDU忙
always_comb
    busy = remainingCycleCount != 0;

// 倒计时机制
always_ff @ (posedge clock) begin
    if (remainingCycleCount != 0)
        remainingCycleCount <= remainingCycleCount - 1;
    
    if (remainingCycleCount == 1)
        // 计算完成，写入HI/LO寄存器
        case (savedOperation)
            MDU_START_SIGNED_MUL:   {hi, lo} <= resultSignedMul;
            // ...
        endcase
end
```

### 问题1️⃣：乘法器被占用时，不使用乘法器的指令(L2)可以正常执行吗？

#### 答案：**不能**正常执行

#### 代码证据 —— [TopLevel.v](src/TopLevel.v#L195-L198)

```verilog
wire stall_mdu = (id_ex_mdu_start || id_ex_mdu_read) && mdu_busy;

assign stallF = hazard_stallF || stall_mdu;
assign stallD = hazard_stallD || stall_mdu;
assign stallE = stall_mdu;
```

**问题分析**：
- `stall_mdu` 会在 `mdu_busy` 为真时暂停整个流水线前端（IF、ID、EX）
- 这意味着 L2 `addu $10, $11, $12` 会被卡在 ID 阶段等待

**为什么会这样？**
- L1 `mult` 在 EX 阶段时设置 `id_ex_mdu_start = 1`，MDU开始工作，`mdu_busy = 1`
- 此时 `stall_mdu = 1 && 1 = 1`，流水线暂停
- L2 虽然不使用MDU，但被一起暂停了

#### 如何修改让L2正常执行？

**方案**：修改stall条件，只在**当前EX阶段指令需要MDU**时才stall

```verilog
// 原代码（保守策略：MDU启动后全部stall）
wire stall_mdu = (id_ex_mdu_start || id_ex_mdu_read) && mdu_busy;

// 修改后（激进策略：只在需要MDU的指令到达EX时才stall）
// 方案1：只在 mflo/mfhi 遇到 busy 时 stall
wire stall_mdu = id_ex_mdu_read && mdu_busy;

// 这样 mult 指令发射后不会 stall，后续无关指令可以继续执行
// 但 mflo/mfhi 会在 MDU 忙时被卡住
```

**注意**：这需要确保 mult 只在 start 时发射一次，避免重复启动。当前代码中 `start(id_ex_mdu_start && !mdu_busy)` 已经处理了这点。

### 问题2️⃣：如何让代码卡在L6而不是L3/L4？

#### 题目要求分析

当前行为：
- L3 `mflo` 在 EX 阶段遇到 `mdu_busy = 1`，stall等待
- L4 `mfhi` 同理
- L6 `addu $3, $3, $4` 正常执行（此时MDU已完成）

期望行为：
- L3/L4 不阻塞，立即执行（但结果暂时不可用）
- L6 阻塞等待 $3/$4 的值就绪

#### 设计思路（提示已给出）

> **提示**：标记 `mflo` `mfhi` 的目标寄存器为未完成，插入气泡。

**实现方案**：

```
1. 引入 "寄存器未完成表"（scoreboard）
   - 当 mflo/mfhi 执行时，标记其目标寄存器(如$3, $4)为"pending"
   - 状态保持直到 MDU 计算完成且数据写回

2. 修改 HazardDetectionUnit
   - 检测后续指令是否使用 pending 状态的寄存器
   - 如果使用，则 stall（类似 load-use 冒险）

3. 数据写回时机
   - L6 恢复前，$3/$4 的值需要从 MDU 结果写入 WB 级
   - 确保流水线恢复时只有一条指令
```

**代码修改草案**：

```verilog
// 新增：寄存器 scoreboard
reg [31:0] reg_pending;  // 32位，每位对应一个寄存器

// mflo/mfhi 执行时标记目标寄存器
always @(posedge clock) begin
    if (id_ex_mdu_read && !mdu_busy) begin
        // mflo/mfhi 正常执行，清除 pending
        reg_pending[id_ex_dest] <= 1'b0;
    end else if (/* mflo/mfhi 在 EX 且 MDU busy */) begin
        // 标记目标寄存器为 pending
        reg_pending[id_ex_dest] <= 1'b1;
        // 不 stall，让 mflo/mfhi 流过（插入结果为0或占位值）
    end
end

// 修改 HazardDetectionUnit：检测 pending 寄存器
wire pending_hazard = (id_use_rs && reg_pending[if_id_rs]) ||
                      (id_use_rt && reg_pending[if_id_rt]);
                      
// 后续指令使用 pending 寄存器时 stall
assign stallF = load_use_hazard || pending_hazard;
assign stallD = load_use_hazard || pending_hazard;
```

## 四、关键信号速查表

### 流水线控制信号

| 信号     | 来源             | 作用                            |
| -------- | ---------------- | ------------------------------- |
| `stallF` | HazardUnit + MDU | 暂停 IF 阶段（PC不更新）        |
| `stallD` | HazardUnit + MDU | 暂停 ID 阶段（IF/ID寄存器保持） |
| `stallE` | MDU              | 暂停 EX 阶段                    |
| `flushE` | HazardUnit       | 清空 EX 阶段（插入NOP）         |
| `flushM` | MDU              | 清空 MEM 阶段                   |

### 转发控制信号

| 信号        | 值      | 含义               |
| ----------- | ------- | ------------------ |
| `forwardAE` | `2'b00` | 使用寄存器文件原值 |
| `forwardAE` | `2'b01` | 从 WB 阶段转发     |
| `forwardAE` | `2'b10` | 从 MEM 阶段转发    |

### MDU 信号

| 信号        | 作用                             |
| ----------- | -------------------------------- |
| `mdu_start` | 启动乘除法运算                   |
| `mdu_read`  | 读取 HI/LO 寄存器                |
| `mdu_busy`  | MDU 正在计算中                   |
| `mdu_op`    | 操作类型（mult/div/mfhi/mflo等） |
