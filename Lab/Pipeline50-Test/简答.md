问题1：怎么识别后执行的指令是否用了前执行的指令还没写回寄存器的内容？
这个现象学名儿叫'数据冒险'，为了答题方便，后面我都以这个词指代题目中的这个现象

在我的作业里，ForwardingUnit.v 实现了"识别数据冒险"的功能
如何做到的呢？我认为主要就是**比较寄存器编号**。

先贴上代码：
```
// ForwardingUnit.v 第17-19行
if (ex_mem_reg_write && !ex_mem_mem_to_reg && 
    (ex_mem_dest != 5'd0) && (ex_mem_dest == id_ex_rs)) begin
    forwardAE = 2'b10;
end
```

解释一下这段代码：它做的事是去检查：
1、当前在EX阶段的指令要读取的源寄存器（`id_ex_rs` 和 `id_ex_rt`）
2、前执行的指令（在MEM阶段或WB阶段）要写入的目标寄存器（`ex_mem_dest` 和 `mem_wb_dest`）

按我自己理解解释一下这段儿内容，主要有四个部分最关键：
1、 `ex_mem_reg_write`，意思是：MEM阶段的指令确实要写寄存器
2、`!ex_mem_mem_to_reg`意思是：不是load指令（load需要特殊处理）
3、`ex_mem_dest != 5'd0`意思是：目标不是$0寄存器（$0恒为0，不需要转发）
4、`ex_mem_dest == id_ex_rs`意识是：MEM阶段要写的寄存器正好是EX阶段要读的寄存器

只有当这些条件都满足时，才算检测到了数据冒险————后执行的指令（当前在EX阶段）用到了前执行的指令（当前在MEM阶段）还没写回的结果。

同样的逻辑也用于检测与WB阶段的冒险（第21-23行）。


问题二，指令 stall 在你的代码里什么地方涉及？你的代码通过什么方法判断需要 stall 几个周期的？

有**两处**涉及stall：

第一，Load-Use冒险的stall （在这个文件里 HazardDetectionUnit.v）

贴上代码：
```
// HazardDetectionUnit.v 第13-15行
wire hazard_rs = id_use_rs && (id_ex_dest != 5'd0) && (id_ex_dest == if_id_rs);
wire hazard_rt = id_use_rt && (id_ex_dest != 5'd0) && (id_ex_dest == if_id_rt);
wire load_use_hazard = id_ex_mem_to_reg && (hazard_rs || hazard_rt);
```
他在检测前一条是load指令（`id_ex_mem_to_reg`为真），且当前指令要用它的结果。
那它是怎么判断stall几个周期的呢？
首先，stall 1周期后，load指令从MEM阶段进入WB阶段
然后，发现这时候数据已经从内存读出，可以通过MEM→EX转发传给后续指令。所以代码直接输出stall信号了
因此显然Load-Use只要stall **1个周期**。

贴上代码以证明我的解释：
```
assign stallF = load_use_hazard;  // stall一次就够
assign stallD = load_use_hazard;
assign flushE = load_use_hazard;  // 插入一个气泡
```

第二处，MDU（乘除法）的stall（TopLevel.v）

```
// TopLevel.v 第195行
wire stall_mdu = (id_ex_mdu_start || id_ex_mdu_read) && mdu_busy;
```

代码并不是预先计算"需要stall N个周期"，而是得每周期检测————只要 `mdu_busy=1`，就继续stall，直到 `mdu_busy=0` 了为止。
而这里的busy信号具体是怎么控制的得看下面代码，有点难直接解释

```
// MultiplicationDivisionUnit.sv
`define MUL_DELAY_CYCLES 5   // 乘法需要5周期
`define DIV_DELAY_CYCLES 10  // 除法需要10周期

// 关键：busy信号由剩余周期计数器决定
always_comb
    busy = remainingCycleCount != 0;  // 计数不为0就是忙

always_ff @(posedge clock) begin
    // 每个时钟周期，计数器减1
    if (remainingCycleCount != 0)
        remainingCycleCount <= remainingCycleCount - 1;
    
    // 启动时，根据操作类型设置初始周期数
    if (start && remainingCycleCount == 0) begin
        case (operation)
            MDU_START_SIGNED_MUL, MDU_START_UNSIGNED_MUL: 
                remainingCycleCount <= `MUL_DELAY_CYCLES;  // 设为5
            MDU_START_SIGNED_DIV, MDU_START_UNSIGNED_DIV: 
                remainingCycleCount <= `DIV_DELAY_CYCLES;  // 设为10
        endcase
    end
end
```

解释一下具体流程：
1、 乘法启动时，`remainingCycleCount` 被设为5，`busy` 立即变1
2、 每个时钟上升沿，计数器自动减1（5→4→3→2→1→0）
3、当计数器减到0时，`busy` 变为0，stall就自动解除

所以MDU的stall周期数是不能提前知道的，只有个大概（乘法约5周期，除法约10周期。），具体得每周期检查 `busy` 信号


问题3：旁路机制是怎么跨流水线转发的？你的代码通过什么方法判断需要使用旁路数据而不是真的寄存器数据？

我的代码里有两条转发路径，分别处理**rs寄存器**和**rt寄存器**：

1、 **MEM阶段 → EX阶段**（前1条指令的结果）：通过 `ex_mem_alu_result` 转发
2、 **WB阶段 →  EX阶段**（前2条指令的结果）：通过 `reg_write_dataW` 转发

数据通过多路选择器（MUX）选择，对应在代码 `TopLevel.v` 的第305-308行：

```
// 对rs寄存器的转发选择
assign forwardA_value = (forwardAE == 2'b10) ? ex_mem_alu_result :  // MEM阶段转发
                        (forwardAE == 2'b01) ? reg_write_dataW :    // WB阶段转发
                                               id_ex_reg_data1;     // 原始寄存器值

// 对rt寄存器的转发选择（同样逻辑）
assign forwardB_value = (forwardBE == 2'b10) ? ex_mem_alu_result :
                        (forwardBE == 2'b01) ? reg_write_dataW : id_ex_reg_data2;
```

转发后的值 `forwardA_value` 和 `forwardB_value` 会被送入ALU去计算。

那怎么判断到底用哪个数据源的呢？这就回到前面提到的 ForwardingUnit.v 了
ForwardingUnit.v 通过以下逻辑判断是否需要转发（拿ai画个表比较直观，以rs寄存器为例）：

| forwardAE值 | 条件                                | 数据来源                             |
| ----------- | ----------------------------------- | ------------------------------------ |
| `2'b00`     | 无冒险（默认）                      | 寄存器文件原值 `id_ex_reg_data1`     |
| `2'b10`     | MEM阶段指令写同一寄存器，且不是load | MEM阶段的ALU结果 `ex_mem_alu_result` |
| `2'b01`     | WB阶段指令写同一寄存器              | WB阶段的写回数据 `reg_write_dataW`   |

**具体判断条件在**（ForwardingUnit.v 的第17-21行）：

```
// 检查是否需要从MEM阶段转发
if (ex_mem_reg_write &&           // MEM阶段指令要写寄存器
    !ex_mem_mem_to_reg &&         // 不是load指令（load的数据在MEM阶段还没出来）
    (ex_mem_dest != 5'd0) &&      // 目标不是$0
    (ex_mem_dest == id_ex_rs))    // 目标寄存器 == 当前指令的rs
begin
    forwardAE = 2'b10;
end
// 检查是否需要从WB阶段转发
else if (mem_wb_reg_write &&      // WB阶段指令要写寄存器
         (mem_wb_dest != 5'd0) && // 目标不是$0
         (mem_wb_dest == id_ex_rs)) // 目标寄存器 == 当前指令的rs
begin
    forwardAE = 2'b01;
end
```
注意MEM阶段转发优先于WB阶段转发。因为是如果两条前序指令都写同一个寄存器，应该使用更近那条（MEM阶段）的结果，因为它的值是相对新的。代码中的 `if-else if` 分支确保了这个优先级。

而rt寄存器（forwardBE）的判断逻辑完全相同，只是把 `id_ex_rs` 换成 `id_ex_rt`。这里就不用再解释了

## II.B) 乘法单元机制分析

问题1：乘法器被占用时，不使用乘法器的指令(L2)可以正常执行吗？

这种情况下，在我当前的代码实现中L2没法正常执行。

看 TopLevel.v 第196-202行：

```verilog
wire stall_mdu = (id_ex_mdu_start || id_ex_mdu_read) && mdu_busy;

assign stallF = hazard_stallF || stall_mdu;
assign stallD = hazard_stallD || stall_mdu;
assign stallE = stall_mdu;
assign flushE = hazard_flushE && !stall_mdu;
assign flushM = stall_mdu;
```

时序上看：
```
周期1: L1(mult)在ID阶段，L2在IF阶段
周期2: L1进入EX阶段，id_ex_mdu_start=1，MDU启动
       这个时候 mdu_busy 变为1（remainingCycleCount=5）
       stall_mdu = 1 && 1 = 1
       → stallF=1, stallD=1, stallE=1
       → L2被卡在ID阶段，无法前进
周期3-6: MDU继续计算，stall_mdu保持为1
         L2一直被卡在ID阶段
周期7: MDU完成，mdu_busy=0，stall解除
       L2终于可以进入EX阶段了
```

问题的关键在于 `id_ex_mdu_start` 被包含在stall条件中。当mult指令在EX阶段时，`id_ex_mdu_start=1`，加上`mdu_busy=1`，会让整个流水线前端都被暂停。

那怎么改能让他可以执行？
得修改stall条件，只在需要读取MDU结果（mflo/mfhi）时才stall：

在代码上就是这么改：
```
// 原代码（保守策略：mult也会触发stall）
wire stall_mdu = (id_ex_mdu_start || id_ex_mdu_read) && mdu_busy;

// 修改后（只在mflo/mfhi需要结果但MDU还在忙时才stall）
wire stall_mdu = id_ex_mdu_read && mdu_busy;
```

修改后的时序：
```
周期1: L1(mult)在ID阶段
周期2: L1进入EX阶段，启动MDU
       id_ex_mdu_start=1, 但 id_ex_mdu_read=0
       stall_mdu = 0 && 1 = 0  ← 不stall
       L2正常进入ID阶段
周期3: L1进入MEM阶段，L2进入EX阶段（正常执行addu）
       MDU在后台继续计算
...
```

同时需要确保 `mult` 只启动一次，不会重复启动。当前代码已经处理了这点：
```
// TopLevel.v MDU实例化部分
.start(id_ex_mdu_start && !mdu_busy)  // 只在MDU空闲时启动
```
这样即使mult指令因为流水线原因在EX阶段多待一个周期，也不会重复启动MDU。


问题2：如何让代码卡在L6而不是L3/L4？

题目要求的行为是：

L3 `mflo $3` 和 L4 `mfhi $4` **不阻塞**，直接执行（但结果暂时不可用）
L6 `addu $3, $3, $4` 在使用 $3、$4 时发现数据未就绪，**此时才阻塞**
L6 恢复执行前，$3、$4 的值需要正确写入

根据提示"标记 `mflo` `mfhi` 的目标寄存器为未完成"，需要引入寄存器记分板机制：

1：新增寄存器状态表 —— 在 TopLevel.v 中
```
// 32位，每位表示对应寄存器是否"数据未就绪"
reg [31:0] reg_pending;

// 记录pending寄存器对应的MDU值来源（用于后续写回）
reg [31:0] pending_mdu_hi [0:31];  // 存储每个pending寄存器应得的HI值
reg [31:0] pending_mdu_lo [0:31];  // 存储每个pending寄存器应得的LO值
reg pending_is_hi [0:31];          // 标记是取HI还是LO
```

2：mflo/mfhi执行时标记目标寄存器
```
always @(posedge clock) begin
    if (reset) begin
        reg_pending <= 32'b0;
    end else begin
        // 当 mflo/mfhi 在EX阶段遇到 MDU busy 时，标记目标寄存器为 pending
        // 让指令继续流过（不stall），但标记结果未就绪
        if (id_ex_mdu_read && mdu_busy && id_ex_dest != 5'd0) begin
            reg_pending[id_ex_dest] <= 1'b1;
            pending_is_hi[id_ex_dest] <= (id_ex_mdu_op == MDU_READ_HI);
        end
        
        // 当 MDU 完成时（busy从1变0），清除所有相关pending标记
        // 并触发写回操作
        if (mdu_busy_prev && !mdu_busy) begin
            // MDU刚完成，需要写回之前pending的寄存器
            for (int i = 1; i < 32; i++) begin
                if (reg_pending[i]) begin
                    reg_pending[i] <= 1'b0;
                    // 触发写回（见步骤4）
                end
            end
        end
    end
end
```
3：修改HazardDetectionUnit，检测pending寄存器
```verilog
// 在 TopLevel.v 或 HazardDetectionUnit.v 中新增检测逻辑
wire pending_hazard_rs = id_use_rs && (if_id_rs != 5'd0) && reg_pending[if_id_rs];
wire pending_hazard_rt = id_use_rt && (if_id_rt != 5'd0) && reg_pending[if_id_rt];
wire pending_hazard = pending_hazard_rs || pending_hazard_rt;

// 合并到stall信号
assign stallF = load_use_hazard || pending_hazard;
assign stallD = load_use_hazard || pending_hazard;
assign flushE = (load_use_hazard || pending_hazard);
```
4：处理写回，这个很容易被人忽略

题目要求："L6 从 EX 级恢复执行前，往 $3 $4 写入应该重新插入回流水线的 WB 级中"

这就得需要一个特殊的写回机制：

```verilog
// 当MDU完成且有pending寄存器时，创建一个"虚拟"的WB级写回
reg pending_writeback_valid;
reg [4:0] pending_writeback_addr;
reg [31:0] pending_writeback_data;

always @(posedge clock) begin
    if (mdu_just_finished && any_pending) begin
        // 依次写回pending的寄存器（可能需要多个周期）
        // 此时流水线仍然stall，保证"一级流水线上只有一条指令"
        pending_writeback_valid <= 1'b1;
        pending_writeback_addr <= first_pending_reg;
        pending_writeback_data <= pending_is_hi[first_pending_reg] ? mdu_hi : mdu_lo;
    end
end

// 在WB级，除了正常的写回，还要考虑pending写回
assign actual_reg_write = reg_writeW || pending_writeback_valid;
assign actual_write_addr = pending_writeback_valid ? pending_writeback_addr : reg_write_addrW;
assign actual_write_data = pending_writeback_valid ? pending_writeback_data : reg_write_dataW;
```

5：mflo/mfhi不stall，直接流过
```
// 修改MDU stall条件
// 原来: wire stall_mdu = (id_ex_mdu_start || id_ex_mdu_read) && mdu_busy;
// 改为: 不因mflo/mfhi而stall，改用pending机制
wire stall_mdu = 1'b0;  // 或者只在mult/div启动冲突时stall
```
总而言之，流程就是
```
周期1: L1 mult $1,$2 在 EX 阶段，启动 MDU（5周期）
周期2: L2 addu 在 EX 阶段，正常执行
       L3 mflo $3 在 ID 阶段
周期3: L3 mflo $3 在 EX 阶段
       MDU busy=1，检测到 id_ex_mdu_read=1
       → 标记 $3 为 pending，但不stall
       → L3 带着无效数据继续流向 MEM（实际不写寄存器）
周期4: L4 mfhi $4 在 EX 阶段
       → 标记 $4 为 pending
周期5: L5 空
周期6: L6 addu $3,$3,$4 在 ID 阶段
       检测到 $3 和 $4 都是 pending
       → pending_hazard = 1
       → stallF=1, stallD=1, flushE=1
       → L6 卡在 ID 阶段！
周期6-?: 继续stall等待 MDU 完成
周期N:   MDU 完成 (busy=0)
         → 将 LO 写入 $3，HI 写入 $4（插入WB级）
         → 清除 $3、$4 的 pending 标记
周期N+1: pending_hazard=0，stall解除
         L6 进入 EX 阶段，此时 $3、$4 已有正确值
```


问题3（附加题）：双乘法器方案

要让L8-L13不阻塞、L14阻塞，需要两个乘法器同时工作，且需要跟踪每个mflo/mfhi应该从哪个MDU获取结果。

`MultiplicationDivisionUnit.sv`里新增双MDU封装模块

```
module DualMDU(
    input logic reset, clock,
    input logic [31:0] operand1, operand2,
    input mdu_operation_t operation,
    input logic start,
    output logic busy,           // 只有两个都忙时才为1
    output logic [31:0] dataRead,
    output logic [1:0] which_mdu_started  // 指示本次启动的是哪个MDU
);
    // 实例化两个独立的MDU
    logic busy0, busy1;
    logic [31:0] dataRead0, dataRead1;
    
    MultiplicationDivisionUnit mdu0 (
        .reset(reset), .clock(clock),
        .operand1(operand1), .operand2(operand2),
        .operation(use_mdu0 ? operation : MDU_READ_HI),
        .start(start && !busy0),  // 优先使用mdu0
        .busy(busy0),
        .dataRead(dataRead0)
    );
    
    MultiplicationDivisionUnit mdu1 (
        .reset(reset), .clock(clock),
        .operand1(operand1), .operand2(operand2),
        .operation(use_mdu1 ? operation : MDU_READ_HI),
        .start(start && busy0 && !busy1),  // mdu0忙时用mdu1
        .busy(busy1),
        .dataRead(dataRead1)
    );
    
    // 调度逻辑
    wire use_mdu0 = !busy0;
    wire use_mdu1 = busy0 && !busy1;
    
    // 只有两个都忙时才报告busy
    assign busy = busy0 && busy1;
    
    // 指示启动了哪个MDU
    always_ff @(posedge clock) begin
        if (start && !busy0)
            which_mdu_started <= 2'b00;
        else if (start && busy0 && !busy1)
            which_mdu_started <= 2'b01;
    end
endmodule
```

TopLevel.v 里新增DualMDU实例
先替换MDU实例为DualMDU
再扩展scoreboard，记录每个pending寄存器对应哪个MDU

```
reg [31:0] reg_pending;           // 哪些寄存器pending
reg [1:0] pending_mdu_id [0:31];  // 每个pending寄存器对应哪个MDU

// mflo/mfhi 标记pending时，同时记录MDU编号
// 每个MDU完成时，只清除对应的pending寄存器
```
时序上看：
```
周期1: L8 mult $1,$2 → 启动 MDU_0
周期2: L9 mflo $3    → MDU_0 busy，标记$3 pending(MDU_0)
周期3: L10 mfhi $4   → MDU_0 busy，标记$4 pending(MDU_0)
周期4: L11 mult $5,$6 → MDU_0 busy，MDU_1 空闲 → 启动 MDU_1
周期5: L12 mflo $7   → MDU_1 busy，标记$7 pending(MDU_1)
周期6: L13 mfhi $8   → MDU_1 busy，标记$8 pending(MDU_1)
       此时 L8-L13 都已经流过，没有阻塞！
周期7: L14 addu $3,$3,$7 进入 ID 阶段
       检测到 $3(pending,MDU_0) 和 $7(pending,MDU_1) 都 pending
       → stall！
周期?: 两个MDU都完成后，写回对应寄存器，L14 才能继续执行
```
