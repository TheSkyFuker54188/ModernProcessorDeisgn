# 实验6：五级流水线CPU设计 - 实验报告

## 流水线竞争处理

在这个实验里，我实现了一个五级流水线的MIPS CPU（IF-ID-EX-MEM-WB），主要难点在于处理三种流水线冒险（Hazard）：数据冒险、Load-Use冒险和控制冒险。

---

## 一、数据冒险处理 —— 数据转发（Forwarding）

### 1.1 问题描述

有时候，后面的指令需要用到前面指令的计算结果，但那个结果还没写回寄存器，就会出现数据冒险。比如：

```assembly
addu $t0, $t1, $t2   # EX阶段算出结果
addu $t3, $t0, $t4   # ID阶段要读$t0
```

### 1.2 解决方案

我用一个转发单元（ForwardingUnit）把EX/MEM或MEM/WB阶段的结果直接绕到EX阶段的ALU输入，这样就不用停顿流水线了。

### 1.3 实现代码

```verilog
// ForwardingUnit.v
module ForwardingUnit (
    input wire ex_mem_reg_write,      // EX/MEM阶段写不写寄存器
    input wire ex_mem_mem_to_reg,     // EX/MEM阶段是不是Load指令
    input wire [4:0] ex_mem_dest,     // EX/MEM阶段目标寄存器
    input wire mem_wb_reg_write,      // MEM/WB阶段写不写寄存器
    input wire [4:0] mem_wb_dest,     // MEM/WB阶段目标寄存器
    input wire [4:0] id_ex_rs,        // 当前EX阶段的rs寄存器
    input wire [4:0] id_ex_rt,        // 当前EX阶段的rt寄存器
    output reg [1:0] forwardAE,       // ALU操作数A的转发控制
    output reg [1:0] forwardBE        // ALU操作数B的转发控制
);
    always @(*) begin
        forwardAE = 2'b00;  // 默认用寄存器堆的值
        forwardBE = 2'b00;

        // EX/MEM阶段转发（优先级高）
        // 条件：EX/MEM要写寄存器，不是Load，目标不是$0，和当前rs匹配
        if (ex_mem_reg_write && !ex_mem_mem_to_reg && 
            (ex_mem_dest != 5'd0) && (ex_mem_dest == id_ex_rs)) begin
            forwardAE = 2'b10;  // 从EX/MEM转发
        end 
        // MEM/WB阶段转发
        else if (mem_wb_reg_write && (mem_wb_dest != 5'd0) && 
                 (mem_wb_dest == id_ex_rs)) begin
            forwardAE = 2'b01;  // 从MEM/WB转发
        end

        // rt也一样
        if (ex_mem_reg_write && !ex_mem_mem_to_reg && 
            (ex_mem_dest != 5'd0) && (ex_mem_dest == id_ex_rt)) begin
            forwardBE = 2'b10;
        end 
        else if (mem_wb_reg_write && (mem_wb_dest != 5'd0) && 
                 (mem_wb_dest == id_ex_rt)) begin
            forwardBE = 2'b01;
        end
    end
endmodule
```

### 1.4 转发路径选择

在 `PipelineTop.v` 里，根据转发信号选ALU输入：

```verilog
// forwardAE决定ALU操作数A从哪儿来
wire [31:0] forwardA_value = (forwardAE == 2'b10) ? ex_mem_alu_result :   // EX/MEM转发
                             (forwardAE == 2'b01) ? mem_wb_write_data :   // MEM/WB转发
                             id_ex_reg_data1;                             // 原寄存器值

// forwardBE决定ALU操作数B从哪儿来
wire [31:0] forwardB_value = (forwardBE == 2'b10) ? ex_mem_alu_result :
                             (forwardBE == 2'b01) ? mem_wb_write_data :
                             id_ex_reg_data2;
```

### 1.5 转发控制信号编码

| forwardAE/forwardBE | 来源               |
| ------------------- | ------------------ |
| 2'b00               | 寄存器堆（没冒险） |
| 2'b01               | MEM/WB阶段结果     |
| 2'b10               | EX/MEM阶段结果     |

## 二、Load-Use冒险处理 —— 流水线停顿（Stall）

### 2.1 问题描述

Load指令后面紧跟着用它的结果的指令，由于Load的数据要到MEM阶段才拿到，转发搞不定，只能停顿一个周期：

```assembly
lw   $t0, 0($t1)    # MEM阶段才拿到数据
addu $t2, $t0, $t3  # 下一条要用$t0
```

### 2.2 解决方案

用冒险检测单元（HazardDetectionUnit）检查Load-Use冒险，发停顿信号让IF和ID停一个周期，清空EX阶段（插气泡）。

### 2.3 实现代码

```verilog
// HazardDetectionUnit.v
module HazardDetectionUnit (
    input wire id_use_rs,           // ID阶段用不用rs
    input wire id_use_rt,           // ID阶段用不用rt
    input wire [4:0] if_id_rs,      // ID阶段rs号
    input wire [4:0] if_id_rt,      // ID阶段rt号
    input wire id_ex_mem_to_reg,    // EX阶段是不是Load
    input wire [4:0] id_ex_dest,    // EX阶段目标寄存器
    output wire stallF,             // IF停顿信号
    output wire stallD,             // ID停顿信号
    output wire flushE              // EX清空信号（插气泡）
);
    // 检查rs冒险
    wire hazard_rs = id_use_rs && (id_ex_dest != 5'd0) && (id_ex_dest == if_id_rs);
    // 检查rt冒险
    wire hazard_rt = id_use_rt && (id_ex_dest != 5'd0) && (id_ex_dest == if_id_rt);
    // Load-Use冒险：EX是Load，ID要用结果
    wire load_use_hazard = id_ex_mem_to_reg && (hazard_rs || hazard_rt);

    assign stallF = load_use_hazard;  // 停IF（PC不动）
    assign stallD = load_use_hazard;  // 停ID（IF/ID不动）
    assign flushE = load_use_hazard;  // 清ID/EX（插NOP）
endmodule
```

### 2.4 停顿控制逻辑

在 `PipelineTop.v` 里用停顿信号：

```verilog
// PC使能：停顿时不动
assign pc_enable = !(stallF || halt_fetch);

// IF/ID写使能：停顿时保持指令
always @(*) begin
    if_id_write_enable = (!stallD) && (!halt_fetch);
end

// ID/EX：Load-Use时清控制信号（插气泡）
always @(posedge clock or posedge reset) begin
    if (reset) begin
        // 复位...
    end else if (flushE) begin
        // 清控制信号，插NOP气泡
        id_ex_reg_write <= 1'b0;
        id_ex_mem_read <= 1'b0;
        id_ex_mem_write <= 1'b0;
        id_ex_branch <= 1'b0;
        id_ex_jump <= 1'b0;
        id_ex_jump_reg <= 1'b0;
        id_ex_is_syscall <= 1'b0;
        id_ex_mem_to_reg <= 1'b0;
    end else if (!stallD) begin
        // 正常传...
    end
end
```

## 三、控制冒险处理 —— 分支/跳转刷新

### 3.1 问题描述

分支指令（beq）和跳转指令（j, jal, jr）在EX阶段才知道跳不跳，这时候IF和ID已经拿错指令了。

### 3.2 解决方案

EX阶段发现要跳，就发刷新信号清IF/ID流水线寄存器，别让错指令跑下去。

### 3.3 实现代码

```verilog
// PipelineTop.v 里的跳/分支检测
wire branch_takenE = id_ex_branch && (forwardA_value == forwardB_value);  // BEQ成立
wire jump_takenE = id_ex_jump;                                             // J/JAL
wire jump_reg_takenE = id_ex_jump_reg;                                     // JR
wire redirect_validE = branch_takenE || jump_takenE || jump_reg_takenE;   // 要不要跳

// 跳目标选
wire [31:0] redirect_targetE = jump_reg_takenE ? forwardA_value :    // JR从寄存器
                               jump_takenE     ? id_ex_jump_target : // J/JAL立即数
                                                 branch_targetE;      // BEQ PC+4+offset

// IF/ID刷新信号
assign flush_if_id = redirect_validE || (is_syscallD && !halt_fetch && !stallD);

// IF/ID刷新逻辑
always @(posedge clock or posedge reset) begin
    if (reset) begin
        if_id_pc <= 32'b0;
        if_id_pc4 <= 32'b0;
        if_id_instr <= NOP_INSTR;
    end else if (flush_if_id) begin
        // 刷新：插NOP，清错指令
        if_id_pc <= 32'b0;
        if_id_pc4 <= 32'b0;
        if_id_instr <= NOP_INSTR;
    end else if (if_id_write_enable) begin
        // 正常更新...
    end
end

// PC更新逻辑
always @(*) begin
    pc_next = pc_plus4;              // 默认PC+4
    if (redirect_validE) begin
        pc_next = redirect_targetE;  // 跳时用跳目标
    end
end
```

## 四、冒险处理总结

| 冒险类型            | 检测条件                                   | 处理方式         |
| ------------------- | ------------------------------------------ | ---------------- |
| **数据冒险（RAW）** | EX/MEM或MEM/WB写寄存器和当前EX源寄存器一样 | 数据转发         |
| **Load-Use冒险**    | EX是Load，ID要用结果                       | 停1周期 + 插气泡 |
| **控制冒险**        | 分支成功或跳指令                           | 刷新IF/ID        |

### 设计要点

1. **转发优先级**：EX/MEM转发比MEM/WB优先（数据新）
2. **$0不参与**：MIPS里$0总是0，不用检测
3. **Load特殊**：Load结果从内存来，EX转不了，必须MEM/WB
4. **控制信号**：Controller的 `uses_rs` 和 `uses_rt` 用来准确定位指令真用源寄存器没
